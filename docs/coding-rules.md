# Правила оформления кода — tender-front

Стек: React 19 · TypeScript 6 (strict) · Vite 8 · TanStack Query 5 · React Router 7 ·
openapi-fetch + openapi-typescript · Tailwind CSS 4 + shadcn/ui · oxlint · Vitest.

Правила — не вкусовщина: у каждого есть причина, и она записана рядом. Если правило мешает,
сначала обсуждаем и меняем этот файл, потом код.

## 1. Язык и стиль

- UI, комментарии и документация — на русском; коммиты и описания PR — на английском.
- Комментарий объясняет **почему** (ограничение API, решение владельца, найденный баг),
  а не пересказывает код. Ссылка на эндпоинт — в формате `POST /auctions/{id}/bids`.
- Форматирование: 2 пробела, одинарные кавычки, без точек с запятой, висячая запятая
  в многострочных литералах, длина строки до ~100 символов.
- Именование: компоненты и типы — `PascalCase`, функции/переменные/хуки — `camelCase`,
  хуки начинаются с `use`, константы-справочники — `UPPER_SNAKE_CASE`
  (`TENDER_STATUS_LABELS`). Файл с компонентом называется как компонент (`BidComposer.tsx`),
  файл с логикой — по смыслу в `camelCase` (`bidRules.ts`).
- Именованные экспорты везде, кроме `App.tsx`. Default-экспорт затрудняет поиск и рефакторинг.

## 2. TypeScript

- `strict` и `noUncheckedIndexedAccess` включены и не выключаются. `any` запрещён;
  неизвестные данные — `unknown` и сужение (type guard).
- Импорт типов — только `import type` (`verbatimModuleSyntax`).
- `as` — только на границе с внешним миром (тело ответа, `JSON.parse`, `FormData`), с
  комментарием, почему приведение безопасно. Внутри приложения тип выводится, а не утверждается.
- `!` (non-null assertion) — только для инварианта DOM (`getElementById('root')`).
- Сравнение с отсутствием — `== null` / `!= null` (ловит и `null`, и `undefined`, а поля
  схемы часто бывают и тем и другим).
- Union-литералы вместо `enum` (`erasableSyntaxOnly`).

## 3. Контракт API — единственный источник правды

- Типы API **никогда** не пишутся руками. Сущности — `components['schemas'][...]`,
  параметры запросов — `operations['opId']['parameters']['query']`, тела — через
  `RequestBody<'opId'>` из `api/types.ts`. Новый эндпоинт → `npm run gen`, а не ручной тип.
- Справочник подписей — `Record<TypeFromSchema, string>`: новое значение в спеке
  компилятор подсветит сам. Свободная строка в схеме — мапа с фолбэком на сырое значение.
- Компоненты не вызывают `client` напрямую — только типизированные обёртки из `src/api/`.
- Обёртка возвращает данные через `unwrap(result)` или `ensureOk(result)` (для ответов без тела).
  Голый `throw result.error` запрещён: он теряет HTTP-статус и `instanceof Error`.
- Абсолютные URL к API в коде запрещены — только `API_BASE` (same-origin + прокси).

## 4. Ошибки

- Все ошибки API — экземпляры `ApiError` (`lib/errors.ts`): `status` (HTTP), `code` (реестр
  ErrorCode или `http_<status>`, если сервер его не прислал), `title`, `detail`, `errors`,
  `retryAfter`. Проверка — `isApiError(e)` / `isApiErrorCode(e, 'forbidden')`.
- Логику строим по `code`, а не по тексту `detail`: тексты API английские и меняются.
- Текст для пользователя — только `apiErrorMessage(e)`.
- Штатные отказы (`403 forbidden` у настраиваемых прав, `404` «профиль не заполнен»)
  объясняются текстом на странице, а не красной ошибкой.

## 5. Серверное состояние — TanStack Query

- Ключи запросов — только через фабрику `queryKeys` (`api/queryKeys.ts`). Литерал ключа в
  компоненте запрещён: опечатка в нём молча ломает инвалидацию.
- Иерархия ключа: `[сущность, ...уточнения]`; инвалидация — по префиксу
  (`queryKeys.tenders.all`), а не перечислением.
- После мутации — `invalidateQueries` по затронутым префиксам; ручной `setQueryData` — только
  когда ответ мутации и есть новое состояние (live-снапшот аукциона).
- Политика ретраев задана в `lib/queryClient.ts`: 4xx не повторяются, сеть и 5xx — ограниченно.
  Не переопределять `retry` в компонентах без причины в комментарии.
- `enabled` — для зависимых запросов (нет компании → нет `GET /companies`), а не условный хук.
- Мутации с побочным эффектом на деньгах/ставках — `useIdempotentMutation`: ключ на действие,
  ретрай переиспользует его.

## 6. React-компоненты

- Только функциональные компоненты и хуки. Правила хуков — ошибка линтера, зависимости
  эффектов указываются полностью; если зависимость не нужна, значение уходит в `useRef`.
- `useEffect` — для синхронизации с внешним миром (EventSource, таймер, DOM). Производные
  данные считаются при рендере или в `useMemo`, а не копируются в state эффектом.
- Файл компонента экспортирует только компоненты (fast refresh). Хуки, контексты и константы,
  нужные снаружи, живут в отдельных модулях (`useAuth.ts`, `auctionStatus.ts`).
- Страница (`*Page.tsx`) собирает данные и раскладку; доменная логика (правила торгов,
  права, расчёты) — в чистых функциях `*.ts` рядом, чтобы её можно было протестировать.
- Компонент больше ~300 строк — сигнал вынести подкомпонент или логику.
- Права и роли — через единые точки (`lib/tenderAccess.ts`, `settingsAccess.ts`), не
  сравнением по месту. Видимость кнопки не заменяет обработку 403.
- Доступность: у поля есть `<label htmlFor>`, у иконочной кнопки — `aria-label`, статус
  загрузки — `role="status"`.

## 7. Роутинг

- Страницы подключаются лениво (`lazy` в `router.tsx`): в начальный бандл идёт только каркас.
- Состояние фильтров и выбранной вкладки — в URL (`useSearchParams`), чтобы ссылкой можно
  было поделиться. URL — единственный источник правды по фильтрам.
- Редирект после логина — только на относительный путь (`safeRedirect`), чтобы `?from=`
  не стал открытым редиректом.

## 8. Деньги, даты, числа

- Суммы — целые minor units (копейки) от API до UI. Float-арифметика с деньгами запрещена.
- Ввод суммы → `parseRublesToMinor` (пробелы, запятая, точный разбор строки без умножения
  float); вывод в поле — `minorToRublesInput`; отображение — только `formatMoney`.
- Даты — ISO-строки из API, вывод через `lib/format.ts`; склонения — `plural`.

## 9. Стили и UI-кит

- Tailwind-классы в разметке; общий примитив — компонент в `components/ui` через shadcn CLI
  (`make ui ARGS="add dialog"`), не руками. Слияние классов — `cn()`.
- Цвета статусов — семантические варианты `Badge` (`success/warning/danger/info/violet/neutral`),
  не произвольные цвета по месту.

## 10. Безопасность

- Access-токен — только в памяти, refresh — `localStorage` (до перехода на HttpOnly-cookie).
- Refresh — только через `refreshTokens()` из `api/client.ts`: он один на вкладку и
  сериализован между вкладками, потому что бэкенд отзывает использованный refresh.
- В `.env` только `VITE_*`, и всё в бандле публично — секретов там нет.
- `dangerouslySetInnerHTML` запрещён.

## 11. Тесты и проверки

- `make check` = lint + typecheck + build + test — то, что гоняет CI; зелёный перед PR.
- Чистая логика (`lib/`, `*Rules.ts`, `liveState.ts`, парсеры) покрывается юнит-тестами
  Vitest рядом с файлом: `money.test.ts`.
- Линтер — 0 ошибок и 0 предупреждений; отключение правила — точечно и с причиной.
