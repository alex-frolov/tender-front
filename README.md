# Tender Front

[![CI](https://github.com/alex-frolov/tender-front/actions/workflows/ci.yml/badge.svg)](https://github.com/alex-frolov/tender-front/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

Single-page client for [**tender**](https://github.com/alex-frolov/tender) — an API-first
e-procurement engine (tenders, sealed bids, live reverse auctions, contracts).

The backend ships 80+ OpenAPI paths but no UI, so it could only be demonstrated through
Swagger UI. This app is that missing UI: a typed React client generated from the same
OpenAPI contract the API serves.

> **Note on language:** the interface is in Russian — the demo targets a Russian-speaking
> procurement audience. Code, commits, and docs are mixed RU/EN; this README is EN.

## Features

- **Tenders** — catalog with filters and cursor pagination, tender card with lots,
  publish / edit / withdraw / cancel gated by the caller's role and company.
- **Bids** — suppliers submit bids, the customer reviews and admits or rejects them.
  Bids stay encrypted until opening, so a blank price column before that is expected
  behaviour, not a bug.
- **Live auctions** — reverse auctions with a real-time feed over Mercure (SSE):
  price, timer, and status update without polling; bids are idempotent under retries.
- **Auth** — login with optional TOTP two-factor, registration, e-mail verification,
  password reset, and silent access-token refresh.
- **Contracts, companies, notifications, users** — supporting screens around the
  procurement flow, including a platform-admin company gate.
- **Settings** — 2FA, API keys, webhooks (with delivery log), platform timezone and
  rate limits, role permissions — each tab shown per the backend's permission matrix.

## Requirements

- **Node.js** `^20.19` or `>=22.12` (Vite 8 / oxlint requirement); npm 10+.
- A running **tender** API on `http://127.0.0.1:8080` for anything beyond the login screen.
  See the [backend README](https://github.com/alex-frolov/tender) for its Docker Compose setup.

## Getting started

```bash
npm install
cp .env.example .env      # optional: defaults work for local development
npm run dev               # http://localhost:5173
```

The dev server proxies `/api` to `http://127.0.0.1:8080` (see `vite.config.ts`), so the
browser talks to a single origin and no CORS setup is needed — the same arrangement as
production, where nginx fronts both the static bundle and the API.

## Environment variables

| Variable | Default | Description |
| --- | --- | --- |
| `VITE_API_BASE` | `/api/v1` | API base URL. Leave empty for a same-origin deployment behind one proxy; set a full URL (e.g. `https://api.example.com/api/v1`) when the API lives on another host. |

Only `VITE_*` variables reach the client bundle, and everything in it is public — never
put secrets in `.env`.

There is no test runner in the project yet; `npm run build` and `npm run lint` are the
checks that gate a change, and CI runs exactly those.

## The OpenAPI contract is the single source of truth

`npm run gen` downloads `openapi.yaml` from the running API and regenerates
`src/api/schema.d.ts`. **API types are never written by hand:**

```ts
import type { components } from '@/api/schema'

type Tender = components['schemas']['Tender']
```

Label dictionaries are declared as `Record<TypeFromSchema, string>`, so when the API adds
an enum value the compiler points at every map that no longer covers it, instead of the UI
silently rendering a raw string.

## Project structure

```
src/
├── api/          # typed wrappers per domain; components never call the client directly
│   ├── client.ts     # openapi-fetch instances (+ auth middleware)
│   └── schema.d.ts   # generated from openapi.yaml — do not edit
├── components/
│   ├── ui/       # shadcn/ui primitives (add via the shadcn CLI, not by hand)
│   ├── layout/   # AppLayout, navigation
│   └── auth/     # route guards
├── features/     # one folder per domain: tenders, bids, auction, contracts,
│                 # company, notifications, settings, users, auth
├── hooks/        # useAuctionStream, useCursorPage, useIdempotentMutation, …
└── lib/          # formatting, money, enums, errors, access rules, auth store
```

Path alias: `@/` → `src/`. `verbatimModuleSyntax` is on, so type-only imports must use
`import type`.

`docs/wireframes.html` is a standalone page with the early screen sketches and the status
colour palette the badges follow — open it in a browser; it is not part of the bundle.

## Implementation notes

A few decisions worth knowing before reading the code:

- **Auth.** The access token lives in module memory only; the refresh token is in
  `localStorage`. A middleware on the API client performs a single-flight refresh on `401`
  and replays the original request, and reports a dead session through an event bus rather
  than importing React code. `/auth/*` calls go through a second, middleware-free client —
  routing them through the main one would make refresh recurse into itself.
- **Live auctions.** `GET /auctions/{id}/stream` returns discovery data (Mercure hub, topic,
  subscriber JWT); the client then opens an `EventSource` and merges each snapshot onto local
  state instead of replacing it, because the hub publishes a partial snapshot on every event.
- **Errors.** API errors follow RFC 9457 and are identified by their string `code`, not by
  HTTP status — `openapi-fetch` puts the response body in `error` as-is.
- **Money.** Amounts are integer minor units end to end. Formatting goes through one helper;
  float arithmetic on money is not allowed.
- **Idempotency.** User-triggered mutations send an `Idempotency-Key`, and React Query retries
  reuse the same key, so a retried auction bid can't be counted twice.

## Continuous integration

[`.github/workflows/ci.yml`](.github/workflows/ci.yml) runs lint, type-check, and build on
every push to `main` and on every pull request, and uploads the production bundle as an
artifact.

`.npmrc` sets `legacy-peer-deps=true` on purpose: `openapi-typescript@7` declares a peer of
`typescript@^5.x` while this project is on TypeScript 6, and `npm ci` fails without it.
